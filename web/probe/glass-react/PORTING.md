# Porting a glass Vue component to React

The React build must render pixel-identical pages to the Vue build. The gate is
`node scripts/glass-diff.mjs` (16 screenshots, zero tolerance). Follow these
rules; each one comes from a difference found while porting the shell.

## Where things are

| Vue | React |
|---|---|
| `@/stores/app` `useAppStore()` | `@/stores/app`: `useApp(s => ...)` to read, `appStore.<action>()` to write |
| `@/stores/nodes` `useNodesStore()` | `@/stores/nodes`: `useNodes(s => ...)`, `nodesStore.<action>()` |
| `snapshot` (`@/captain`) | `useBox(snapshot)` from `@/hooks/useBox`, `snapshot` from `@shared/captain` |
| `@/composables/useX` | `@/hooks/useX` (same names; plain values instead of refs) |
| `@/components/ui/*` | `@/components/ui/*` (same names; `class` → `className`, slots → props/children) |
| `<VChart :option autoresize />` | `<EChart option={...} autoresize />` from `@/components/EChart` |
| `<Transition ...>` | `@/components/Transition` (same props; the child must forward `ref` to its root element) |
| `useRoute/useRouter` | `@/lib/router` |
| `onActivated/onDeactivated` (KeepAlive) | `useActivation(onActivated, onDeactivated)` from `@/lib/router` |
| `inject('isScrolled')` | `useContext(ScrolledContext)` from `@/components/Provider` |
| `@iconify/vue` `Icon` | `@iconify/react` `Icon` (same props) |
| `t()` | `t` from `@shared/i18n` (unchanged) |

Framework-neutral code lives in `glass-shared/` (`@shared/...`). Import it; never copy it.
If a Vue component contains a sizeable pure function you need too, move it into
`glass-shared/` and make the Vue file import it, then confirm the Vue build still
passes the gate (see Verification).

## Rules that keep pixels identical

1. **Same DOM.** Same elements, nesting, class strings (character for character,
   same order inside `cn(...)`), attributes, inline styles and text.
2. **Text whitespace.** Vue condenses template whitespace: a run that contains a
   newline between text and an element becomes ONE space; whitespace between two
   elements disappears; leading/trailing whitespace inside an element is kept as a
   single space when it is next to text. JSX drops newline whitespace. When in
   doubt, look at the compiled Vue bundle (`dist/glass/assets/*.js`) for the exact
   string literals, and write them explicitly, e.g. `{' Powered by '}`.
   `{{ a }} / {{ b }}` → write one template literal `{`${a} / ${b}`}`.
3. **Class bindings.** `:class="cond && 'x'"` with a falsy `cond` adds nothing.
   `:class="[a, b]"` and object syntax join with single spaces; use `cn` only where
   the Vue code used `cn`, otherwise build the string as Vue would.
4. **Scoped styles.** If the Vue file has `<style scoped>`, its compiled CSS is
   already in `@/scoped/<kebab-name>.css` (generated by
   `scripts/glass-scoped-css.mjs`). Import it and reproduce Vue's `data-v-*`
   placement with `scope('<kebab-name>')` from `@/scoped/scope`:
   - every element written in this component's template gets the attribute,
     including elements passed as slot content/children into another component;
   - for a child *component* used in this template, only the child's root
     element gets this component's attribute (pass it as a prop; ui primitives
     spread extra props onto their root); the child's own internals do not;
   - if this component's own root is another component (e.g. NodeCard's root is
     CardX), that root element also receives the PARENT's scope attribute,
     because Vue gives a component's root the parent's id too. So a scoped
     component must accept extra props (`...rest`) and forward them to its root.
   Verified on the reference build: NodeCard's root element carries NodeCard's
   and HomeView's ids; CardX's inner elements carry none.
   `:deep()` selectors are already compiled. `v-bind()` CSS variables: names are
   in `scopes[name].vars`; set them as inline style on the component root.
   Unscoped components (most of them) need none of this, except forwarding
   extra props to their root so a scoped parent's attribute lands there.
5. **v-if/v-else** → conditional rendering; **v-show** → `style={{ display: 'none' }}`
   when hidden (Vue writes `display: none;` and removes it when shown, leaving
   `style=""` if no other style).
6. **Lists.** `v-for` with `:key` → `.map` with the same key.
7. **Timing.** Vue's `onMounted` and `watch(..., { immediate: true })` run before
   the first paint; use `useLayoutEffect` (or compute during render) when the
   result affects what is painted first. `watch` without `immediate` → effect that
   skips the first run. `nextTick` → `queueMicrotask` after the commit.
8. **Async components** (`defineAsyncComponent`) → `React.lazy` + `Suspense` with
   no fallback (Vue renders nothing while loading).
9. **Do not add behaviour.** No visitor IP lookups, external requests, analytics.
   Captain's public API only.

## Verification you must run

From `web/probe`:

```sh
pnpm exec tsc -b glass-react/tsconfig.json      # 0 errors (never --noEmit or -p)
pnpm exec oxlint glass-react/src                # 0 errors
pnpm exec vue-tsc -b glass/tsconfig.json        # only if you touched glass/ or glass-shared/
```

If you moved code into `glass-shared/`, rebuild the Vue bundle and gate it against
the reference build; it must PASS:

```sh
pnpm exec vite build --config vite.glass.config.ts
node scripts/glass-diff.mjs --ref ../../../glass-ref/web/probe/dist/glass --cand dist/glass --out /tmp/<you>-vue-gate
```

The React page cannot be gated as a whole until HomeView/InstanceDetail exist;
the lead integrates and gates. Report every place where you were unsure the DOM
matches.
